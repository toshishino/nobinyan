# uta-timer-server

Twitch / YouTube の「初コメ」「投げ銭」「サブギフト」を検知して、
タイマー画面（uta-timer.html）にWebSocketでリアルタイム通知する中継サーバーです。

## セットアップ

```bash
npm install
cp .env.example .env
# .env は WS_PORT や STREAMER_ID など、めったに変えない項目だけ確認すればOK
npm start
```

サーバー起動後、ブラウザで **http://localhost:8787/** を開くと設定画面が表示されます。
Twitchチャンネル名やギフト種別のon/off、YouTube連携などはここから設定でき、
`.env`を編集してサーバーを再起動する必要はありません（保存すると即座に反映されます）。

## Twitch を使う場合
- 設定画面（http://localhost:8787/）で「Twitch連携を有効にする」をオンにし、チャンネル名（表示名ではなくログイン名）を入力して保存してください
- 匿名IRC接続で読み取り専用なので、Twitchアカウントの認証情報は不要です
- 検知イベント：
  - 初コメ → **その配信で初めて発言した人**（サーバー起動後のセッション単位で判定。生涯初コメントかどうかは問いません）
  - ギフト加算の対象は3種類、設定画面でそれぞれon/off切り替え可能：
    - 投げ銭（Bits）
    - サブスク（新規登録・継続）
    - サブスクギフト（贈られたサブスク）
  - offにしてもDBへの記録（常連ランキング用）は続きます。タイマーに反映されなくなるだけです

## YouTube について

現在は既定で無効化しています。コードは実装済みなので、設定画面から「YouTube連携を有効にする」を
オンにし、APIキーと配信中の動画IDを入力すれば使えます。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成し「YouTube Data API v3」を有効化してAPIキーを発行
2. 設定画面でAPIキーを入力（一度保存すれば、次回以降は空欄のままでOK。既存の値が保持されます）
3. 配信を開始したら、配信URL (`https://www.youtube.com/watch?v=XXXXXXXXXXX`) の `XXXXXXXXXXX` 部分を「配信中の動画ID」に入力して保存
4. 配信ごとに動画IDが変わるので、配信のたびにこの値を更新してください（サーバーの再起動は不要です）
5. 検知イベント：
   - 初コメ → **その配信で初めて発言した人**（Twitchと同じくセッション単位で判定）
   - 投げ銭 → スーパーチャット / スーパーステッカー
   - サブギフト → メンバーシップギフト

※ YouTubeはポーリング方式のためAPIクォータを消費します。長時間配信では消費量にご注意ください。

## 初コメ判定の仕組み・注意点

初コメは「**その配信で初めて発言したか**」で判定します。常連さんでも、その配信枠での最初の発言なら初コメ扱いです。

- 判定はサーバー起動時にリセットされるメモリ上のセッション（Twitch/YouTubeそれぞれ）で行っています
- **重要**：サーバーを再起動せずに複数の配信をまたいで常駐させると、2回目以降の配信で常連さんが初コメ判定されなくなります。配信を開始したら、**設定画面（http://localhost:8787/）の「初コメ判定をリセット」ボタン**、または**タイマー画面の「配信開始：初コメ判定をリセット」ボタン**を押してください（どちらもサーバー再起動は不要です）
- YouTubeは配信ごとに`YOUTUBE_VIDEO_ID`を更新してサーバーを再起動する運用なので、通常はそのタイミングで自然にリセットされます

## タイマー画面との接続

`uta-timer.html` をブラウザで開くときにURLパラメータを付けます。

```
uta-timer.html?ws=ws://localhost:8787
```

OBS表示用の大画面モードと併用する場合：

```
uta-timer.html?obs=1&ws=ws://localhost:8787
```

サーバーが検知すると、画面上部のバッジが「自動検知：接続中」になり、
初コメ・投げ銭・サブギフトが来るたびに自動でタイマーが加算されます
（手動ボタンはそのまま残っているので、誤検知の修正や併用も可能です）。

## 視聴者DB（常連ランキングの土台）

`db.js` が SQLite（`viewers.db`）に発言者を記録します。**初コメ判定には使いません**（それは上記のセッション単位の判定が担当）。ここは生涯累計データとして、将来の常連ランキング機能（フェーズ4）のために蓄積しています。

- **発言記録**：Twitch/YouTubeどちらも、発言のたびに `comment_count` を積み上げます
- **ギフト記録**：投げ銭・サブギフトの回数も `gift_count` として蓄積されます

### 常連ランキングを見る

```bash
node ranking.js                 # 全プラットフォーム、発言数トップ10
node ranking.js twitch          # Twitchのみ
node ranking.js youtube gifts   # YouTubeのみ、ギフト数ランキング
node ranking.js all gifts 20    # 全プラットフォーム、ギフト数トップ20
```

### DBファイルについて
- 既定では `uta-timer-server/viewers.db` に保存されます（`.env`の`DB_PATH`で変更可）
- 他配信者に配布する場合は `.env` の `STREAMER_ID` を配信者ごとに変えることで、
  同じDBファイルでもデータが混ざらないようにしてあります
- 視聴者のIDやニックネームを蓄積する仕組みなので、配布する際は「発言履歴をローカルに保存している」旨を一言説明しておくと親切です

## 既知の制約
- YouTubeは配信ごとに `YOUTUBE_VIDEO_ID` の手動更新が必要です（配信中に自動取得したい場合は `liveBroadcasts.list` + OAuth への拡張が必要）
- 常時稼働させるには、GitHub CodespacesやOracle Cloudなどでサーバーを起動しっぱなしにしておく必要があります
- `better-sqlite3` はネイティブモジュールなので、環境（OS/Nodeバージョン）を変えると `npm install` の再実行が必要な場合があります
