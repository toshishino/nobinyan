# 歌枠タイムカウンター 仕様書

## 1. 概要

歌枠（歌配信）向けの加算式カウントダウンタイマー。基本時間に加えて、視聴者の
初コメントやギフト（投げ銭・サブギフト）に応じて時間が延長される仕組みを持つ。
Twitch / YouTube の両方に対応し、チャットイベントを自動検知してタイマーに反映する。

対象ユーザーは配信者本人（作者）。将来的には他配信者への配布も視野に入れる。

---

## 2. タイマーのルール

| 項目 | 内容 | 既定値 |
|---|---|---|
| 基本時間 | 配信枠の持ち時間 | 30分 |
| 初コメ加算 | 視聴者が初めて発言するごとに加算 | +5分 / 人 |
| ギフト加算 | 投げ銭・サブギフト1個ごとに加算 | +10分 / 個 |
| 手動修正 | カウント間違い等の補正用 | ±1分 |

基本時間・各加算値は設定パネルから変更可能。

**「初コメ」の定義**
- **その配信で初めて発言した人**。常連さんであっても、その配信枠での最初の発言であれば初コメとして扱う（生涯初めての発言かどうかは問わない）
- サーバー起動＝配信開始とみなし、起動時にリセットされるセッション単位のメモリ管理（Set）で判定する
- Twitch公式の`first-msg`タグ（生涯初コメント）はこの定義とは意味が異なるため使用しない
- YouTubeもTwitchも同じロジック（セッション単位の判定）で統一している
- サーバーを再起動せずに複数配信をまたいで常駐させる場合は、設定画面またはタイマー画面のボタンから初コメ判定だけをリセットできる

**「ギフト」の定義**
ギフト加算の対象は3種類あり、それぞれ独立してon/off設定できる（設定画面から変更、DBに保存）。offにしてもDB記録（常連ランキング用）は続くが、タイマーには反映されない。

- 投げ銭（Twitch: Bits）
- サブスク（Twitch: 新規登録・継続）
- サブスクギフト（Twitch: 贈られたサブスク、単発・まとめ贈り両方）

YouTube対応時は、投げ銭＝スーパーチャット/スーパーステッカー、サブスクギフト＝メンバーシップギフトに相当する（YouTube自体の視聴側「サブスク」に相当する概念はメンバーシップ登録だが、現バージョンでは未対応）。

## 3. システム構成

```
┌────────────────┐        ┌───────────────────────┐        ┌──────────────────────┐
│ Twitch チャット │──IRC──▶│                       │        │                      │
│ (匿名接続)      │        │  中継サーバー(Node.js)  │──WS───▶│  タイマー画面(ブラウザ) │
├────────────────┤        │  server.js            │        │  uta-timer.html      │
│ YouTube         │─API──▶│  + db.js(SQLite)      │        │  (OBSでキャプチャ)    │
│ Live Chat API   │ポーリング│                       │        │                      │
└────────────────┘        └───────────────────────┘        └──────────────────────┘
```

- **タイマー画面（uta-timer.html）**：単体で動作するHTML。手動ボタンだけでも運用可能。`?ws=`パラメータを付けると中継サーバーと接続し自動加算になる。`?obs=1`でOBS用の大画面表示モードになる。
- **設定画面（http://localhost:8787/）**：中継サーバーが提供するWeb UI。Twitchチャンネル名、ギフト種別のon/off、YouTube連携などをここから設定でき、`.env`の編集やサーバー再起動は不要。保存すると即座に反映される。
- **中継サーバー（uta-timer-server/）**：Twitch・YouTubeのチャットイベントを監視し、正規化したイベントをWebSocketでタイマー画面に配信する。視聴者情報をSQLiteに蓄積する。設定画面・WebSocket・データ配信はすべて同じポート（既定8787）で待ち受ける。

両者が同一プロセスである必要はなく、タイマー画面は中継サーバーが起動していなくても手動運用できる（自動検知は任意機能という位置づけ）。

## 4. コンポーネント詳細

### 4.1 タイマー画面（uta-timer.html）
- 単一HTMLファイル、ビルド不要
- カウントダウン表示、延長トラック（加算履歴を可視化するバー）、履歴ログ
- 操作：スタート/一時停止/リセット、初コメ+5分ボタン、ギフト+10分ボタン（個数指定可）、手動±1分
- キーボードショートカット：`Space`（開始/一時停止）、`C`（初コメ+5分）、`G`（ギフト+10分）
- URLパラメータ：
  - `?obs=1` … 操作パネルを隠し、透過背景・大画面表示にする
  - `?ws=ws://host:port` … 中継サーバーに接続し自動加算を有効化

### 4.2 中継サーバー（server.js）
- **稼働環境**：今回はTwitchのみ運用。YouTube対応のコードは実装済みで、設定画面から後から有効化できる
- **設定の永続化**：Twitchチャンネル名・ギフト種別on/off・YouTube設定はDBの`app_settings`テーブルに保存される。初回起動時のみ`.env`の値で初期化され、以降は設定画面からの変更がDBに保存される
- **設定変更の即時反映**：設定画面で保存すると、Twitchは必要に応じて再接続、YouTubeは必要に応じてポーリングの開始/停止が自動で行われる（サーバー再起動不要）
- **セッション管理**：サーバー起動時に「この配信で発言した人」を記録するSet（Twitch/YouTubeそれぞれ）を初期化する。これが初コメ判定の唯一の基準。設定画面（`POST /api/reset-session`）またはタイマー画面のボタン（WebSocket経由）から、再起動せずにリセット可能。
- **Twitch**：`tmi.js`で匿名IRC接続（読み取り専用、認証不要）
  - `message`イベント → セッションSetに無ければ初コメとしてブロードキャスト、DBにも生涯累計として記録
  - `cheer`イベント → 投げ銭（設定画面のトグルでon/off）
  - `subscription` / `resub`イベント → サブスク（設定画面のトグルでon/off）
  - `subgift` / `submysterygift`イベント → サブスクギフト（設定画面のトグルでon/off）
  - いずれもoffの場合、DBへの記録（常連ランキング用）は続けるが、タイマーへの通知はしない
- **YouTube**（設定画面で有効化した場合のみ動作）：`YouTube Data API v3`の`liveChat.messages`をポーリング
  - 動画IDから`liveChatId`を取得
  - 発言イベントでセッションSetを確認 → 無ければ初コメとしてブロードキャスト、DBにも生涯累計として記録
  - `superChatEvent` / `superStickerEvent` → 投げ銭
  - `membershipGiftingEvent` → サブスクギフト
  - `pageToken`をDBに永続化し、サーバー再起動時の二重カウントを防止
- 検知したイベントはすべて `{ source, type, user, ... }` 形式に正規化してWebSocketでブロードキャスト

### 4.3 視聴者DB（db.js, SQLite）
`viewers` テーブルで発言者を管理する。**初コメ判定には使わず**、将来の常連ランキング（フェーズ4）専用の生涯累計データとして蓄積する。`app_settings`テーブルで設定画面から変更した内容を永続化する。

```sql
viewers (
  streamer_id, platform, viewer_channel_id,   -- 複合ユニークキー
  display_name,
  first_seen_at, last_seen_at,
  comment_count, gift_count
)
```

`youtube_state` テーブルで配信ごとのポーリング位置（`pageToken`）を保持し、再起動時の重複検知を防止する。

`streamer_id` を持たせることで、将来複数配信者に配布した場合もデータが混ざらない設計にしてある。

### 4.4 常連ランキング（ranking.js）
- `node ranking.js [platform] [comments|gifts] [limit]` でCLI表示
- 発言数・ギフト数のランキングをDBから集計

## 5. 設定項目（.env）

| 変数 | 説明 |
|---|---|
| `WS_PORT` | サーバーのポート（設定画面・WebSocket共通、既定8787） |
| `STREAMER_ID` | 配信者識別子（配布時のデータ分離用、既定`default`） |
| `DB_PATH` | SQLiteファイルの保存先（省略可） |
| `ENABLE_TWITCH` 等 | 初回起動時のみ使用する初期値。以降は設定画面（http://localhost:8787/）から変更しDBに保存される |

## 7. 既知の制約・注意点

- 初コメ判定は「サーバー起動時からのセッション」を基準にするため、**サーバーを再起動せず複数配信をまたいで常駐させると、2回目以降の配信で常連さんが初コメ扱いされない**。配信開始時にサーバーを再起動するか、設定画面またはタイマー画面のリセットボタンを押す運用が必須
- YouTubeは配信ごとに動画IDの更新が必要（設定画面から更新するだけでよく、サーバー再起動は不要）
- Twitch匿名接続でサブギフト等のUSERNOTICE系イベントが受信できない場合、Botアカウント＋OAuthトークンでの接続に切り替える必要がある（要検証）
- `better-sqlite3`はネイティブモジュールのため、実行環境（OS/Nodeバージョン）を変える際は`npm install`のやり直しが必要な場合がある
- 視聴者のID・表示名をローカルDBに保存する仕組みのため、他配信者へ配布する際はその旨を明記する想定
- 常時稼働にはCodespacesやOracle Cloud等でサーバーを起動しっぱなしにする必要がある
